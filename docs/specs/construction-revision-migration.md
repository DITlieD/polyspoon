# Construction revision compatibility

Built-in recipes advance from 0.5.0 to 0.6.0: work-lantern, cottage, tree, fence, crate and boulder. Contributed recipes advance from 1.0.0 to 1.1.0: bench, planter, treasure-chest, wheelbarrow, stone-well and conifer. Fence geometry is unchanged; its grouped built-in source package advances with the other built-ins.

Inputs are format-version-1 designs with a known family, supported recipe version, requested parameters, matching applied parameters, optional validated migration notice and optional version-1 appearance. Current saves produce the new recipe version. Loading a supported older design first validates the original record using its frozen validation rules, then supplies the validated applied parameters to the current save path. Earlier supported built-in versions retain their existing strict loader chains. Parameters retain their meanings; this does not replay old geometry.

Reject unknown versions, fields, invalid domains or relationships, altered or incomplete applied records, malformed appearance and forged migration metadata. Never infer validity from the supplied applied record. Unknown symbol fields also reject. A migrated current save retains an exact validated notice across reload and ordinary session edits, history and family selection; reset explicitly starts a fresh design. Browser loading, CLI and MCP use the existing canonical load/export result and its migration notice.

Part colors retain exact supported semantic names. New parts use authored colors. Missing names remain stored and inactive. Indexed component layouts can change between revisions; a retained index denotes its named component in the new arrangement, not an old geometric location. Old cottage roof-band names do not alias to the new course/segment names. Cottage ridge-cap-0 through ridge-cap-3 retain their colors; ridge-cap-4 and ridge-cap-5 start with authored materials. Conifer foliage tier/branch/spray names remain foliage components despite authored shade-role changes. Masonry indices remain course segments after segment-count changes. No unrelated component alias is introduced.

The boulder controls describe width/depth as shape scales and height before burial. Burial reduces exposed height. Default width 1.6, height 0.95, depth 1.2 and burial 0.12 produce approximately 1.76 × 0.84 × 1.38 m. Moss coverage describes continuous growth over the upper surface and shoulders. Only labels/hints change; all keys, defaults, ranges, units, parsing and solids remain fixed.

Focused tests exercise prior/current/earlier versions, tampered and unknown records, colored cottage ridge and absent parts through loadDesign, DesignSession and resolveExport. Geometry functions and source assets stay byte-identical. Prior public modules and source ZIPs stay byte-identical. This phase does not generate packages, previews, builds or renders, or update historical expected hashes. The pure acceptance test is added only to the current unit suite; the stdio acceptance test is added only to the integration suite; historical conflicts are reported separately.

## MCP saved-design intake

The existing build_variant and export_asset tools accept an optional strict design record. That branch uses resolveExport and carries the validated migration notice and appearance into the returned configuration and GLB. Family is optional with a design; a supplied family must match. Reject design combined with parameters or appearance, including an explicitly empty parameters object. Do not add preset support. The existing family branch still requires family and uses empty parameters as family defaults when omitted. Retain export directory identity, exclusive/no-follow creation and both source-provenance guards. A focused actual-stdio test records requests, rejection responses, exported GLB validation and process closure.
